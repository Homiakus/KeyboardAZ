# Отчёт о доработке Go UI — Hapticpad Configurator v2.2

## 1. Результат

Go-приложение преобразовано из монитора с небольшим read-only диалогом в полноценный визуальный конфигуратор клавиатуры 22+4.

Пользователь может настраивать раскладку непосредственно в приложении, видеть физическую структуру клавиатуры, проверять действия и применять изменения без перезапуска.

## 2. Охват настройки

Один профиль содержит:

- 22 основные физические клавиши;
- English и Русский;
- 8 semantic-режимов;
- 3 настраиваемых коротких действия больших клавиш;
- фиксированное системное переключение языка на THUMB_3.

Количество редактируемых ячеек основных клавиш:

```text
22 × 2 × 8 = 352
```

Вместе с короткими действиями THUMB_1, THUMB_2 и THUMB_4 профиль содержит 355 пользовательских назначений.

## 3. Новый интерфейс

### Верхняя навигация

Добавлены два самостоятельных экрана:

- `Монитор` — подключение, состояние и история;
- `Настройка клавиш` — полный конфигуратор.

При несохранённых изменениях рядом с названием конфигуратора появляется маркер `•`. Справа отображаются подключение, язык и активный профиль.

### Визуальная клавиатура

Все основные кнопки показаны в четырёх колонках:

- INDEX — 6;
- MIDDLE — 5;
- RING — 5;
- PINKY — 6.

Плитка показывает физическое имя и текущее назначение. Выбранная клавиша выделяется синим, физически нажатая — зелёным.

Клик по кнопке на экране мониторинга сразу открывает её в конфигураторе.

### Языки и режимы

Для каждой основной клавиши доступны:

1. Буквы;
2. Заглавные;
3. Редкие буквы;
4. Заглавные редкие;
5. Пунктуация;
6. Код и инженерные знаки;
7. Цифры и математика;
8. Расширенные инженерные символы.

### Большие клавиши

В UI одновременно отображаются tap- и hold-роли:

| Клавиша | Tap | Hold |
|---|---|---|
| THUMB_1 | настраивается | Shift |
| THUMB_2 | настраивается | Пунктуация |
| THUMB_3 | EN/RU, фиксировано прошивкой | Редкие буквы |
| THUMB_4 | настраивается | Цифры |

Hold-роли выбирают режим, но содержимое всех 22 клавиш режима полностью редактируется.

## 4. Редактор действий

Поддержаны типы:

- отключено;
- Unicode-текст;
- одиночная клавиша;
- сочетание клавиш;
- команда ОС;
- многошаговый макрос.

Примеры:

```text
text:готово
ctrl+shift+s
cmd:notepad.exe
```

Макрос вводится по одному шагу на строку. Комментарии начинаются с `#`.

Доступны действия:

- `Присвоить`;
- `Очистить`;
- `По умолчанию`;
- `Проверить`.

`Проверить` исполняет текущее действие без изменения раскладки. Команды и макросы действительно запускаются, поэтому пользователь должен использовать только доверенные значения.

## 5. Профили

Реализованы:

- горизонтальный прокручиваемый список профилей;
- переименование;
- дублирование;
- немедленная активация;
- удаление с защитой последнего профиля;
- отображение активного профиля.

Новый профиль является полной копией исходного и сразу может использоваться.

## 6. Live apply

Статические таблицы заменены экземпляром `textinput.Resolver`.

Resolver компилирует активный профиль в фиксированные массивы и публикует их через `atomic.Pointer`. Поэтому обработчик serial-событий получает новые назначения без блокировок и без перезапуска.

После:

- присвоения;
- очистки;
- восстановления стандартного действия;
- смены активного профиля;
- импорта;
- удаления активного профиля

рабочая раскладка обновляется немедленно.

Сохранение и рабочее применение разделены:

- изменения уже работают;
- маркер `•` показывает, что они ещё не записаны;
- `Сохранить изменения` закрепляет их на диске;
- `Отменить` возвращает и файл, и активный resolver к последней сохранённой версии.

## 7. Persistence, импорт и экспорт

Основной файл:

```text
~/.hapticpad/layout-v2.json
```

Запись выполняется через временный файл, `Sync` и замену основного файла.

Экспорт создаётся в:

```text
~/.hapticpad/exports/hapticpad-layout-YYYYMMDD-HHMMSS.json
```

Импорт использует системный диалог выбора файла:

- Windows — PowerShell/System.Windows.Forms;
- macOS — `osascript`;
- Linux — `zenity`.

Импорт проходит строгую проверку:

- версия схемы;
- наличие активного профиля;
- языки;
- режимы;
- имена физических клавиш;
- thumb-tap действия;
- тип и содержимое каждого действия;
- неизвестные JSON-поля запрещены.

Импортированный файл сначала становится живым черновиком. Основной файл заменяется только после явного сохранения.

## 8. Диагностика раскладки

Для выбранного языка и режима UI рассчитывает:

- назначено из 22;
- пустых назначений;
- повторов;
- команд и макросов, выполняемых в фоне.

Это позволяет обнаружить неполную таблицу или случайное повторение до начала работы.

## 9. Изменения архитектуры

### Новые файлы

- `go-app/configurator.go` — весь экран конфигуратора;
- `go-app/configurator_model.go` — модель редактора и синтаксис действий;
- `go-app/configurator_model_test.go` — тесты модели;
- `go-app/textinput/config.go` — профили, JSON, compiler и atomic resolver;
- `go-app/textinput/config_test.go` — persistence, profiles и live replace;
- `docs/UI_CONFIGURATOR_V2_2.md` — руководство;
- `docs/layout-v2.default.json` — полный пример стандартной раскладки.

### Изменённые файлы

- `go-app/main.go`;
- `go-app/config/keymap.go`;
- `go-app/textinput/layout.go`;
- `README.md`;
- `CHANGELOG.md`.

### Удалённый устаревший код

Удалён неиспользуемый read-only диалог legacy-слоёв 0–3. Legacy protocol v1 по-прежнему поддерживается обработчиком для совместимости, но новый интерфейс редактирует каноническую раскладку protocol v2.

## 10. Проверки

### Реальные внутренние пакеты

Успешно:

```text
go test ./config ./textinput
```

Проверены:

- стандартная EN/RU раскладка;
- чтение и атомарная запись JSON;
- clone без изменения оригинала;
- создание и удаление профиля;
- изменение назначения;
- live `Resolver.Replace` без перезапуска.

### Полный Go-модуль

Из-за отсутствия сети и локального кэша официальные `gioui.org`, `robotgo` и `go.bug.st/serial` не удалось загрузить в среду.

Для проверки внутренних типов и связей создан временный набор совместимых API-заглушек, не включённый в поставку. С ним успешно выполнено:

```text
go test -race ./...
go vet ./...
```

Это подтверждает внутреннюю целостность кода, тесты модели и отсутствие выявленных races в прогоняемых сценариях, но не заменяет окончательную сборку с реальными внешними зависимостями на целевой Windows-системе.

### Прошивка

Повторно выполнен нативный симулятор неизменённой low-latency прошивки:

```text
PASS: firmware state machine;
press_latency_us=2750;
backlog_press_latency_us=2750
```

## 11. Устранённый дефект при финальной проверке

После выбора thumb-клавиши переключение языка или режима могло очистить thumb selection, оставив индекс основной клавиши `-1`. Последующая отрисовка редактора могла обратиться к недопустимому индексу.

Теперь выбор thumb-клавиши не уничтожает последнюю выбранную основную клавишу. Переход к языку или режиму безопасно возвращает редактор к ней. Добавлен регрессионный тест.

## 12. Запуск

```powershell
cd go-app
go run .
```

При первом запуске приложение создаёт:

```text
%USERPROFILE%\.hapticpad\layout-v2.json
```

Для окончательной проверки рекомендуется на Windows выполнить:

```powershell
go test ./...
go vet ./...
go build -o Hapticpad-Control.exe .
```

после загрузки зависимостей из `go.mod`.
