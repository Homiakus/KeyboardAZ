# KeyboardAZ — глубокий аудит и план развития

Дата аудита: 3 августа 2026 года  
Проверенная ветка: `main`, commit `03158749d26d8dcd34847e69946d7dabd9312571`

## Резюме

Проект уже содержит сильное низколатентное ядро: firmware protocol v2, отдельные очереди realtime/macro/background, атомарную конфигурацию раскладки, защиту повторного закрытия ресурсов и нативную симуляцию state machine. Основной технический долг сосредоточен не в тракте ввода, а вокруг него: desktop lifecycle, сборка, выпуск, структура GUI и эксплуатационная диагностика.

В этой итерации реализованы наиболее безопасные улучшения, которые не меняют протокол и не добавляют задержку ввода:

- единый `manage.ps1` для проверки среды, установки инструментов, тестирования, сборки, прошивки, запуска и создания release ZIP;
- `KeyboardAZ.cmd` как простая точка входа для пользователя Windows;
- нативный Windows tray через Win32 API без второго GUI-фреймворка;
- автоматическое скрытие в трей при сворачивании;
- команды трея: открыть, скрыть, открыть папку конфигурации, выйти;
- глобальная комбинация `Ctrl+Shift+F12` для показа/скрытия окна;
- CI для Go core, Windows desktop build и нативной симуляции firmware;
- тест политики minimize-to-tray.

## Архитектурная оценка

| Область | Состояние | Риск | Вывод |
|---|---|---:|---|
| Firmware state machine | сильное | низкий | Фиксированные структуры, timestamp debounce, startup guard и тест симуляции подходят для дальнейшей оптимизации. |
| Protocol v2 | хорошее | низкий/средний | Формат детерминирован, но ASCII CDC остаётся источником транспортного jitter. |
| Realtime action path | сильное | низкий | Физический ввод отделён от макросов и фоновых команд. |
| Serial lifecycle | приемлемое | средний | Переподключение работает, но ownership reader/state распределён между несколькими методами. |
| GUI state ownership | проблемное | высокий | `main.go` превышает 1200 строк, а `configurator.go` — около 900; lifecycle, состояние, рендеринг и команды смешаны. |
| Desktop lifecycle | доработано | средний | До этой итерации приложение завершалось вместе с окном и не имело трея. Добавлен независимый Win32 tray. |
| Build/release | доработано | высокий → средний | Ранее существовали отдельные и противоречивые скрипты; теперь есть единый control center. |
| CI | доработано | высокий → средний | Добавлены форматирование, race tests ядра, vet, benchmark, Windows compile и firmware simulation. |
| Документация | слабое | высокий | Корневой README фактически отсутствовал. Он заменён эксплуатационной документацией. |

## Подтверждённые проблемы

### P0 — отсутствие единого воспроизводимого выпуска

Существовали отдельные `build-firmware-v2.ps1`, `go-app/build-and-run.ps1`, `tests/run-low-latency-checks.ps1` и большой legacy script. Они по-разному обрабатывали ошибки, выходные каталоги и зависимости. `go-app/build-and-run.ps1` также перезапускал PowerShell с `ExecutionPolicy Bypass`, что не нужно для штатной сборки.

**Исправление:** новый `manage.ps1` стал единой точкой оркестрации и поддерживает как интерактивное меню, так и автоматические действия через `-Action`.

### P0 — desktop-приложение не предназначено для постоянной фоновой работы

Companion app должен оставаться запущенным, потому что именно он преобразует semantic strokes в Unicode/keyboard events. До изменения сворачивание оставляло обычное окно в taskbar, а закрытие полностью останавливало обработчик.

**Исправление:** Windows tray запускается в отдельном message-only окне. Сворачивание Gio-окна приводит к `SW_HIDE`; восстановление доступно из трея и через `Ctrl+Shift+F12`.

### P1 — монолитный GUI

`App` одновременно владеет:

- serial connection;
- reconnect state machine;
- action handler;
- resolver и профили раскладки;
- navigation;
- всеми widgets;
- history;
- rendering;
- platform file dialogs.

Это увеличивает стоимость изменений и вероятность гонок. UI нельзя полноценно тестировать без компиляции всего desktop stack.

**Рекомендуемое продолжение:** разделить на `application`, `connection`, `desktop`, `ui/dashboard`, `ui/configurator`, `platform/dialogs`. `AppSnapshot` сохранить как read model, но формировать его отдельным store.

### P1 — привязка трея к заголовку окна

Текущая безопасная реализация не вмешивается во внутреннее окно Gio и находит его по стабильному title. Это позволяет не использовать приватные Gio API, но title нельзя менять независимо.

**Следующий этап:** вынести название приложения в одну константу и передавать native window handle через небольшой platform adapter, когда Gio предоставит стабильный публичный путь.

### P1 — неструктурированное журналирование

Используется стандартный `log.Printf`; нет уровней, ротации, session ID, счётчиков reconnect/parse/drop и экспортируемого диагностического пакета.

**Рекомендация:** добавить ring-buffer diagnostics и JSONL-файл в `%LOCALAPPDATA%\KeyboardAZ\logs`, не логируя каждое нажатие.

### P1 — CDC ASCII как транспорт realtime events

Firmware оптимизирована, но USB CDC и строковый parser создают дополнительный scheduler/driver jitter. Это не ошибка текущей версии, а предел архитектуры.

**Рекомендация:** composite USB с Raw HID interrupt endpoint для strokes и CDC только для управления. Выпускать только после HIL-тестирования на реальном RP2040 и Windows.

### P2 — конфигурация хранится в домашнем каталоге

`~/.hapticpad` работает, но не соответствует нативным путям Windows и не поддерживает portable mode.

**Рекомендация:** миграция в `%LOCALAPPDATA%\KeyboardAZ`, с чтением старого пути и атомарным переносом.

### P2 — UI требует следующего структурного прохода

Текущий dashboard функционален, но перегружен ручной отрисовкой, фиксированными размерами и англо-русским смешением. Наличие нескольких локальных `widget.List` затрудняет сохранение scroll-state.

**Рекомендация по новому UI:**

1. Левая компактная навигация: «Состояние», «Раскладка», «Профили», «Диагностика», «Устройство».
2. Верхняя status strip: устройство, COM-порт, firmware, язык, latency mode.
3. Главная карточка подключения с одним primary action вместо отдельных Connect/Disconnect.
4. Визуальная клавиатура как центральный рабочий объект; параметры выбранной клавиши — справа.
5. Отдельная диагностическая панель с reconnect attempts, sequence gaps и последней ошибкой.
6. Адаптивные breakpoints для 900/1200/1600 px вместо жёсткой компоновки.
7. Единая русская локализация пользовательских строк и английские технические идентификаторы только в detail views.

## Проверки этой итерации

Проведена автономная cross-compilation Win32 tray-модуля для `windows/amd64` с `CGO_ENABLED=0`. Это подтверждает корректность типов, build tags и Win32 вызовов на уровне компилятора. Полный desktop build и HIL-проверка выполняются workflow `quality` и локальным пунктом `Run all tests`.

Физическая проверка всё ещё обязательна для:

- появления и восстановления иконки в Windows 10/11;
- поведения после Explorer restart;
- прошивки реального Pico через BOOTSEL;
- end-to-end input latency;
- прав доступа при вводе в elevated-приложения.
